# 安卓对局、观战和出牌卡顿热修复

用户仅确认上述场景卡顿，没有确认是否由背景设置引起。本轮不将背景作为根因。

实际 QML 回归测试发现两处额外开销：

- `CounterHost` 每秒在界面线程遍历整个对象树。在包含约 3500 个节点的本机 Qt 6.8.3 场景中，五次对局扫描约 1580 毫秒，事件循环最长间隔约 300.7 毫秒。
- `SocialHost` 对每条游戏消息都执行好友状态绑定；1000 条模拟移动牌、卡牌、技能和属性消息造成 1000 次 `contextChanged`，即使好友面板隐藏且状态没有变化。

修正如下：

1. 安卓对局与观战期间禁止全对象树定时扫描。新弹窗只扫描弹窗自己的子树，保留选将弹窗缩放。
2. 记牌器改由 `Ltk.roomScene` 变化挂接与释放。客户端未初始化时才重试，牌堆入口搜索最多补试三次，之后保留记牌器备用入口。
3. 好友处理只响应账号、房间、对局生命周期和好友邀请等相关消息。相同状态不替换好友上下文对象。

同一测试机、同一场景的修复后结果：五次对局全树扫描为 0 毫秒，最长事件循环间隔约 17.1 毫秒；1000 条普通游戏消息约 3 毫秒、好友上下文变化 0 次。记牌器与牌堆入口挂接、选将弹窗缩放、对局/观战隐藏好友、返回大厅恢复入口、原版功能页隐藏入口均通过，没有 QML 类型或引用错误。

这些数值是桌面 Qt 测试，不是安卓真机帧率，也不能证明已经消除用户设备上的全部卡顿。实体手机尚未连接，仍需在原卡顿设备采集数据和复测。

仅改变安卓自定义运行时三个 QML 文件和相应资源清单。原生引擎、游戏核心、服务器校验、Java 辅助 DEX、包名和签名身份沿用原版。iOS、PC 安装包本轮不变。
