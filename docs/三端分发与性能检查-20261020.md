# 三端分发与性能检查 · 2026-10-20

Android 当前 r3 收到“疑似改善，仍待后续测试”的反馈，本轮保留 APK 原字节，不要求用户更换 Android 包。iOS 新增“游玩一段时间后卡顿”的反馈；尚无该 iPhone 的持续性能采样，因此不将本轮自动测试作为真机问题已经解决的证明。

## 分发检查

- 本地五个安装/更新包均与原 SHA256SUMS 一致。iOS 整合包中的 IPA 与独立 IPA 完全相同。
- PC 完整压缩包、更新补丁及已解压分享文件夹的三个自定义 QML 文件一致。
- iOS、PC 原始分发文件与各自维护源码一致；原 iOS 包使用 Qt 6.8.3，PC DLL 版本为 Qt 6.10.0。
- 两端所带 freekill-core 的 Git HEAD 可解析，完整对象检查通过；没有重写核心包或服务器校验输入。
- 未在受检分发路径发现维护者的账号/好友配置数据库、个人好友身份或签名私钥。`packages.db` 是扩展包数据库，Git config 是下载源配置，随包的 PEM 为公共信任证书，不能仅凭这些名称判为泄露账号。
- GitHub 的早期三端发布入口仍带更旧的 APK/IPA，需同步已有资产和校验清单，避免下载入口不一致。

## 已确认并修正的额外开销

原 iOS 与 PC 仍每秒遍历整个界面对象树，而且普通卡牌、技能、属性消息也重新绑定好友状态。这些问题已在 Android r3 修正，本轮将相同原则应用于 iOS 与 PC，保留各端已有的头像、好友身份派生和界面兼容逻辑。

1. 对局/观战中停止周期性的全树遍历；进入新场景只适配一次，新弹窗只适配自己的子树。
2. 通过 `Ltk.roomScene` 的变化挂接/释放记牌器；客户端初始化期间才重试，牌堆搜索补试最多三次。
3. 普通游戏消息不触发好友上下文刷新；内容相同时不替换上下文，也不反复写本地好友资料。
4. 原版功能页关闭后仍可恢复好友入口；对局、观战时保持隐藏。

## 验证范围

测试使用实际 QML 和对应 Qt 版本，游戏/网络服务使用确定性替身，不向实际好友发送邀请。

- iOS：Qt 6.8.3；PC：Qt 6.10.0；Android r3 再次回归使用 Qt 6.8.3。
- 各端连续 60 次新建房间界面、进入对局、打开弹窗、进入观战、返回大厅并销毁场景，共处理 6 万条模拟普通游戏消息。
- 修复后普通游戏消息造成的好友上下文变化为 0；对局中的五次全树扫描被跳过。受测窗口拥有的对象数量回到初值，没有受测类型的净增长。
- 使用真正的 Qt 事件循环，并处理 DeferredDelete；仅反复调用 processEvents 会延后销毁，产生虚假的对象增长。
- iOS 原有服务器说明换行、版本字号、技能说明、三张可见手牌、阴阳状态切换、白色聊天图标及退出文字布局测试通过。

这些是桌面软件渲染和生命周期测试，没有测量 iPhone GPU、温度、持续内存压力，也不是实际联网对局帧率。仍需反馈 iPhone 在原场景持续游玩复测；不能据此宣称全部长期卡顿已消除。
