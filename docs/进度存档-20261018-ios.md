### 2. CI 已修复的坑（勿回退）

1. GitHub runner 的 Python 是 PEP 668 externally-managed → aqtinstall 装进 venv。
2. iOS Qt 交叉编译要 `QT_HOST_PATH` → 额外装 macOS 桌面 Qt 6.8.3（clang_64）。
3. Qt iOS 包不含 `Qt6GuiPrivate` → 内置 v6.8.3 的 4 个 RHI 头到
   `ios-compat/rhi/`，iOS 不依赖 GuiPrivate。
4. Qt Multimedia 的 FFmpeg 插件引用 `av_*` 但静态构建不自动链接 FFmpeg →
   调用 `qt6_add_ios_ffmpeg_libraries(FreeKill)` 链接并嵌入 5 个动态 xcframework。
5. `soloud_miniaudio.cpp` 在 iOS 会包含 AVFoundation → 该文件按 ObjC++ 编译。
6. `qt_add_qml_module` 的 `IosImports.qml` 绝对路径 → 设 `QT_RESOURCE_ALIAS`。
7. Xcode 15.4 的 `ibtool` 不认 `--minimum-deployment-target/--target-device` →
   只用 `--compile`。
8. `genfkver.sh` 在 Windows checkout 没有执行位 → CMake 改为 `sh genfkver.sh`，
   并在 git index 里 `chmod +x`。
9. 嵌入的 FFmpeg framework 未签名 → 禁用 Xcode code-sign-on-copy，构建后
   ad-hoc `codesign --force --sign -`。
10. Windows HTTPS 推送被重置 → remote 改 SSH over 443。

### 3. Windows 一键整合包

入口：`apk/整合包/一键安装到iPhone.cmd`（根目录有本机 `.lnk`）。

脚本 `bin/install-to-iphone.ps1` 会：

1. 自提权（UAC）；
2. 检查 iTunes/Apple 驱动；优先 `winget install Apple.iTunes`，失败则运行随包
   `iTunes64Setup.exe` 向导；
3. 检查 Sideloadly；没有则运行 `SideloadlySetup64.exe /S` 静默安装，失败则打开向导；
4. 尝试启动 `Apple Mobile Device Service`；
5. 把 IPA 路径复制到剪贴板；
6. 打开 Sideloadly，并尝试把 IPA 作为参数带上（不生效就手动拖入）。

**仍必须人工完成（苹果强制）**：

- UAC / SmartScreen 允许；
- 数据线连 iPhone，手机上「信任此电脑」；
- Sideloadly 里填免费 Apple ID（双重认证用 App 专用密码）→ Start；
- iPhone：设置 → 通用 → VPN 与设备管理 → 信任证书。

**当前电脑状态（2026-10-18）**：iTunes 和 Sideloadly **都还没安装**，
`Apple Mobile Device Service` 不存在；一键脚本**尚未实际执行过**（需要用户 UAC）。
脚本做过 PowerShell 语法解析，未做真实安装测试。

### 5. 免费 Apple ID / 只有手机

- 免费 Apple ID 就是普通 Apple 账号（`account.apple.com` 或 iPhone 设置创建），
  不是开发者会员，不需要 $99；Sideloadly 里直接填邮箱/密码（2FA 用 App 专用密码）。
- 免费账号：签名 7 天、最多 3 个 App。
- **只有手机、没有电脑**：免费 Apple ID 首次仍需电脑端签名/配对一次；
  装好后 App 独立运行，但 7 天后要再签。
  - 折中：SideStore（首次电脑配对，之后手机续签；支持范围以官方文档为准，
    iOS 17 具体小版本有差异）。
  - 真正手机-only：付费 Apple Developer + TestFlight（$99/年）。
  - ESign/Feather 等手机端签名需要证书，免费证书不稳定，不建议。
