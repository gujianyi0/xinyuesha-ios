# iOS 武将牌标记只显示首次数据

用户在 iOS 反馈“诡伏”“化身”等标记仅记录一次，后续数量或内容不更新。截图同时涉及标记文字、数量，以及点击标记后显示的牌名/武将信息。

## 根因与修正

PhotoModel 的 marks / picMarks 使用 `property list<var>`。Qt 6.8 从这些列表读取对象时会返回 QVariantMap 的 JavaScript 包装副本。LtkLuaUtil.setMark 首次调用使用 push，能够正常显示；后续调用只给 `elem.value / origValue / qml / desc` 赋值，既没有写回列表，也没有通知已有委托。

在 iOS 从当前核心生成的独立前端中，将已有标记更新改为替换对应列表元素，保持原顺序，并同时发布数量、原值、详情组件参数与描述。新增、删除和零值清除沿原规则处理，没有增加定时器或全树刷新。游戏核心工作文件与校验输入不改动，服务器模式和技能计算不变。Android / PC 本轮不变。

## 回归范围

使用真实 Qt 6.8.3、PhotoModel 的原始标记列表和实际 MarkArea / PicMarkArea 委托：

- 文字数量连续从 1 到 4，图片数量从 2 到 5；
- 化身武将列表从三个替换为一个，点击详情的数据同步替换；
- 自定义标记的文字和武将详情替换；
- 图片标记描述随值更新；
- 特殊牌堆数量与可见牌详情更新，隐藏牌仍不进入可见详情；
- 清除所有标记后再添加。

修正前数量与内容保持初值，断言失败；修正后上述用例通过。云端工作流同时检查捆绑核心和既有服务器核心生成的前端，包含 iOS 原生适配代码的编译与实际 QML 更新测试。

本轮需要新的原生 iOS 程序，因为适配代码嵌在程序中。安装时沿用原应用标识与兼容签名覆盖，不先卸载。Qt 回归并不替代 iPhone 真机对局验收，实际“诡伏”“化身”技能的联网操作仍需用户复测。
