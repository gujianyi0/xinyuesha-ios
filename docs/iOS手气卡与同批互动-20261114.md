# 手气卡与同批互动 · 20261114.1

维护者报告 iOS 自动手气卡每点一次只换一次，手动关闭后再次换牌又会弹出。新增官网反馈 FB-VG38WH 要求全员送花／砸蛋同时发送，正文为“如题”，设备 iOS、版本不清楚，无附件或补充讨论。

## 修正

- 原生 `lua/client/client.lua` 在每个 AskFor 回调前先通知 `CancelRequest`；旧控制器把每次换牌的前置信号当作手气卡结束。现在立即暂停待发操作，短暂等待后继请求；只有没有替代请求的真正取消才结束。
- 自动回复记录自己的待确认答复，兼容同步和排队回调，避免把自己的 `ReplyToServer` 当作手动接管。每个有效请求仍至多回复一次，沿用房间的次数和截止时间。
- 关闭按钮记录本轮关闭状态，后续手动换牌不再重新弹出；下一轮手气卡询问恢复显示，自动模式仍须手动启动。切后台、离房、录像、旁观、过期请求及真正手动接管仍停止。
- 全员送花／砸蛋将点击时的有效玩家快照在同一个界面回合同批发出，移除人为的 1.6 秒逐人延迟；沿用原 Chat 消息和服务器广播。保留共用十秒冷却、砸蛋排除自己、旁观／重复目标过滤及投递中离房停止。
- 共同逻辑同步 Android、PC、iOS，保留各平台原有鼠标滑块、背景回调和画面适配。

## 验证边界

产品提交 `6396255`，[三端 CI 43535820747](https://github.com/gujianyi0/xinyuesha-ios/actions/runs/43535820747) 全成功。原测试将自身回复模拟为同步，也遗漏原生 CancelRequest 前置事件；补充排队回复后先复现“已转为手动操作”旧失败，修正后 23 项手气卡回归通过，包括同请求元数据连续三次换牌、命中保留、关闭保持及真正取消。

互动实测夹具内同批跨度为 0ms，触屏／鼠标、冷却、防重入、目标过滤、发送中离房、原资料与单人互动均通过。Android/iOS 使用 Qt 6.8.3，PC 使用 Qt 6.10.0。夹具和云端回归不代表真实 iPhone 完整对局或外服其他客户端的动画严格同步，网络与服务器的实际效果仍待复测。
